# lpinvestors schema

PostgreSQL schema for the Investor Tracker's entity graph: government-backed
LP commitments, fund vehicles, and the portfolio companies they invest in,
resolved to canonical IDs. Full design rationale: [`../docs/DESIGN.md`](../docs/DESIGN.md).

## Applying

Run the files in `migrations/` in numeric order against a PostgreSQL 13+
database:

```sh
for f in db/migrations/*.sql; do psql "$DATABASE_URL" -f "$f"; done
```

Or via `npm run db:migrate` (see [`../scripts/apply-migrations.sh`](../scripts/apply-migrations.sh)),
which also regenerates the Prisma client afterward.

There's no migration framework wired up (Flyway/sqitch/Alembic/etc.) --
these are plain numbered SQL files, matching `dtfunding`'s convention.
Files are numbered in dependency order (`org` before `fund`, which
references it); they get edited/renumbered in place as the design evolves
rather than accumulating patch-on-patch history, at least until there's a
real deployment target beyond the current single Neon project.

Prisma (`prisma/schema.prisma`) is a **read layer generated by introspecting
this schema** (`prisma db pull`), not a migration tool in its own right --
never run `prisma migrate` against this schema. This mirrors `dtfunding`;
it deliberately does not mirror `founderfluence`, which is Prisma-managed
end to end. The schema here is dense with cross-entity resolution logic
(the actual point of this module, per `docs/DESIGN.md` #2) that's easier to
reason about and comment as hand-written SQL than as a generated migration
diff.

## Design overview

### Entities (`0002_org.sql`, `0003_fund_and_programme.sql`)

- **`org`** -- one record type for GPs, LPs, government bodies, and
  portfolio/founder companies, keyed by a `uuid` with Companies House
  number (`crn`) as the resolution anchor where available. `org_kind`
  classifies the row; `is_quilt_tagged` is the scoping flag that bounds the
  investor tracker's universe to companies QUILT has already tagged as
  frontier tech (docs/DESIGN.md #1) -- set via the QUILT read-join, not
  owned data.
- **`person`** -- PSC-disclosed individuals, deliberately a separate entity
  type from `org`: PSC individuals are mostly founders/controlling
  shareholders, not the LP/investor population (docs/DESIGN.md #3).
  Composite natural key (name + DOB month/year + nationality) mirrors how
  Companies House itself disambiguates PSCs -- there's no stable person-id
  in source data.
- **`fund`** -- fund vehicles, distinct from their GP (`gp_org_id`, an
  `org`) and their LPs (via `commitment`). Secondary record under the
  LP-primary framing: explains how capital reached a company, not a full
  profile subject.
- **`programme`** -- government programmes/sub-funds, one row each. "BBB"
  is not one umbrella (`docs/data-sources.md`): British Patient Capital,
  British Growth Partnership, ECF, and the Nations and Regions funds each
  carry their own `disclosure_url` and `confidence` rating.

### Relationships (`0004_commitments_and_investments.sql`, `0005_psc_and_person_roles.sql`)

- **`commitment`** -- Funder -> Fund, an LP commitment. `amount_gbp` is
  often null (e.g. SNIB discloses an aggregate across funds, not a
  per-fund figure) -- don't backfill a null with a guess.
- **`investment`** -- Fund or direct-investing org -> portfolio company,
  sourced from cap-table extraction (CS01 shareholder-list deltas timed
  against SH01 rounds -- SH01 alone gives round timing, not investor
  identity; see docs/DESIGN.md #2). Exactly one of `investor_org_id`/
  `investor_fund_id` is set (enforced by `investment_one_investor`).
- **`psc_control`** -- individual -> company, from the PSC register
  directly.
- **`person_role`** -- individual -> fund or org (`general_partner`,
  `officer`), unwinding a corporate GP to the people behind it. Exactly one
  of `fund_id`/`org_id` is set.

### Entity resolution (`0006_entity_resolution.sql`)

The actual build (docs/DESIGN.md #2). Resolution priority, reflected in
`resolution_method`:

1. **`crn_match`** -- Companies House number as primary key, wherever a
   filing provides one.
2. **`alias_table`** -- `org_alias` maps a raw surface-form name ("BBB",
   "British Patient Capital") to its canonical `org`/`fund` row for the
   subsidiary/trading-name problem.
3. **`manual_review`** -- unresolved names sit in `resolution_queue` rather
   than being force-merged. A false merge is worse for this dataset than a
   duplicate row staying split.

### Output (`0007_crowd_in_out.sql`)

- **`crowd_in_out`** -- per company: grant-only / govt-equity-only / both /
  neither. `has_direct_grant` comes from a read-join against QUILT's grant
  list on `crn` at query time -- grant data is never duplicated into this
  schema (docs/DESIGN.md #3). This is the module's actual deliverable; see
  docs/DESIGN.md #6.

### Views (`0008_views.sql`)

- **`v_govt_backed_cascade`** -- Funder -> Programme -> Fund -> portfolio
  company, traced end to end, filtered to QUILT-tagged companies.
- **`v_investor_summary`** -- one row per canonical `org`, with alias count
  and commitment/investment counts -- a sanity check on entity-resolution
  coverage.

## Not modelled here

Grant data (QUILT/Innovation Funding Explorer) is out of scope by design --
read access only, joined on `crn`, never a duplicated copy. See
`docs/DESIGN.md` #3 and #5 for the integration contract.
