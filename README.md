# lpinvestors — Investor Tracker

Public-sector LP intelligence: which government-backed investors put capital into which
funds, and which companies those funds (and those investors) hold stakes in.

This is the **Investor tracker**, one of five modules in a longitudinal intelligence
stack tracking frontier-technology policy through to grants, investment, and regulatory
support. It is a *proposed* (not yet built) component; the other four —
[QUILT](#sibling-modules), the funding stack analyser (`dtfunding`), Founderfluence, and
the (also-proposed) Policy tracker — are documented in the architecture briefing this
design is derived from.

**Scope, deliberately narrow:** not a general-purpose investor database. The universe is
investors holding stakes in companies QUILT has already tagged as frontier tech —
QUILT's ontology is the filter that keeps entity resolution bounded.

## Stack

Next.js (TypeScript) on **Render**, **Neon** Postgres — matching `dtfunding` and
`founderfluence`, not QUILT's plain Postgres+Python. Schema conventions mirror
`dtfunding` specifically: hand-written SQL migrations are the source of truth, Prisma is
a read layer generated by introspection (`prisma db pull`), never `prisma migrate`. See
[`db/README.md`](db/README.md#applying) for why, and [`docs/DESIGN.md`](docs/DESIGN.md#9-open-questions-for-the-user)
for what's still open.

## Local dev quick-start

```bash
# 1. Postgres running locally
createdb lpinvestors_test

# 2. .env
cp .env.example .env
# edit .env: set DATABASE_URL to point at lpinvestors_test, and AUTH_PASSWORD

# 3. Install deps, apply migrations, generate the Prisma client
npm install
npm run db:migrate   # applies db/migrations/*.sql, then prisma db pull + generate

# 4. Run
npm run dev
```

The app is a single shared-password admin tool (see `src/lib/auth.ts`), not multi-user
auth — `AUTH_PASSWORD` gates the whole app via `src/proxy.ts`.

`/api/health` runs a real `SELECT 1` against the database, for use by an
uptime/keepalive check.

> **Scaffold verified.** `npm install`, `npm run db:migrate` against a local Postgres,
> `tsc --noEmit`, `npm run lint`, `npm run build`, and `npm run dev` (with `/api/health`
> returning `{"ok":true}` and `/login` reachable) all pass. The earlier note here said
> this hadn't been checked because the sandbox that drafted the scaffold couldn't reach
> the npm registry — that's since been re-run on a machine with real registry access and
> confirmed clean.

## Deployment

| Service | Role | Notes |
|---|---|---|
| **Neon** (Postgres) | Production database | Pooled connection string as `DATABASE_URL`. Migrations are applied separately via `npm run db:migrate`, not as part of the app deploy — see `render.yaml`. |
| **Render** (web service) | App hosting | Config in `render.yaml`. Build: `npm install && npx prisma generate && npm run build`. Start: `npm run start`. Requires `DATABASE_URL` and `AUTH_PASSWORD` set in the Render dashboard (not synced from this repo). |
| **GitHub Actions** (`.github/workflows/keepalive.yml`) | Keeps Neon + Render warm | Cron every 6h + manual dispatch, hits `${{ vars.APP_URL }}/api/health`. Requires the repo variable `APP_URL` set to the deployed base URL. |

## The one-sentence architecture

> Entity resolution — collapsing name variants into one canonical investor ID — is the
> actual build. Everything else (cap-table extraction, government LP monitoring) reuses
> extraction that already exists or is well understood.

## Sibling modules

| Module | Status | Role |
|---|---|---|
| QUILT | Built | Innovate UK grant data, classified by a Deep Tech Ontology. Defines this module's company scope. |
| Funding stack analyser (`dtfunding`) | Built | Capital structure from Companies House filings (SH01/CS01/AR01). Source of cap-table extraction this module reuses. |
| Founderfluence | Built | Founder Mode framework tested against interviews/press. |
| Policy tracker | Proposed | Six-category policy taxonomy over strategy documents. Cross-references named leaders against this module's PSC/GP identities. |
| **Investor tracker** | **Proposed (this repo)** | Investor entity graph scoped to frontier-tech company stakes. |

All five resolve to a company via its **Companies House number** — the join key for the
"connecting repository" that turns five separate tools into one longitudinal panel.
